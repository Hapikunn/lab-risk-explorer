想定するラボは、どこまで自動化されているか

装置・能力・人の介在を説明する調査資料／2026-10-13

1. 最初に伝えたいこと

今回のデモは「受注から出荷まで完全無人の施設」を必須としない。外部から依頼・検体を受け取り、ソフトウェアが複数装置の実行と結果の対応を管理する、現場スタッフ付きのラボを基本想定にする。 これは今回の設計提案で、特定施設の実装を再現したものではない。

実在するクラウドラボには、人とロボットが協働する運用がある。ECLの公式文書は、作業をManualとRoboticに分け、前者をオペレーター、後者を分注ワークセルが実行すると説明する。[S04] ECL利用経験を報告する2024年論文も、ソフトウェアによる工程・実行待ちの管理と、人が自動装置と協働する混成運用を記述している。[S05]

無細胞合成の限定した閉ループ実験では、設計・実行・解析の反復を自律化した例もある。ただし、試薬準備、装填・回収、システム監督などに人が残る。[S08][S10] 遠隔利用できること、装置が自動実行すること、次の実験を自律決定すること、施設全体が無人であることは別である。

用語の区別

用語 この資料での意味
部分自動化 分注など決めた作業を装置が実行。計画・装填・搬送などは別の担当が行う
統合自動化 複数装置の命令・順序・データをソフトウェアが連携させる
クラウドラボ 利用者が遠隔から実験を依頼し、データを受け取る利用形態
閉ループ／自律実験 結果の解析が次の実験条件の選択につながり、反復を進める
受注から出荷まで無人 受領・補充・保守・例外処理・梱包まで含む。今回調べた資料では一貫した無人運用を確認できない

2. 実在例A：Biomek／Echoを使う部分自動化

Biomek i5はピペットによる液体操作のワークステーション。公式ページには25のデッキ位置、分注ヘッドの選択肢、グリッパー、デッキ内外の装置統合などが示される。[S01] Echoは音響による微量分注の装置で、ここでは650を装置カテゴリの例として扱う。[S02] 研究室にあるEchoの型番・構成は未確認。

装置の例 できること それだけでは分からないこと
Biomek i5 設定した手順で分注・液体移送を実行。構成に応じてラボウェアを移動 受注・検体内容の確認・次の実験の決定まで自動か
Echo 650の例 微量の非接触分注 実際の設置機種、他装置との搬送・データ連携
温調装置・プレートリーダー 反応条件の維持、蛍光などの測定 現研究室の機種と分注器からの自動搬送の有無

比較用の運用想定：人が計画を設定し、試薬・プレートを置き、装置を実行し、必要な装置間移送と結果確認を行う。毎回すべてを手入力するとは限らず、保存したメソッドを再利用できる。この運用像は説明のための想定で、木賀研の監査結果ではない。

現行メーカーサイトのソフトウェア機能を、研究室のBiomekソフト5.1.11にもあると推定しない。接続方式・ライセンス・導入オプションは現物で確認する。

3. 実在例B：ECL／CMUの遠隔・統合ラボ

ECLでは利用者が検体を送り、Command Centerで実験を設計し、施設で実行した結果をデータベース上で受け取る。[S03] 公式説明はHPLC、質量分析、NMRなどの幅広い装置を挙げている。[S06] 施設全体の能力と、特定の依頼で利用できる操作は区別する。

人が入力しないと動かないのか

利用者は初めに実験の目的・条件をソフトウェアに記述する。ECLの利用報告では、コードを実行命令へ変換し、実行待ちとデータアップロードをソフトウェアが管理する。[S05] したがって、利用者が各装置を手で操作するモデルとは異なる。ただし、全装置で手動転記が一切ないことや、施設内に人がいないことまでは確認していない。

4. 実在例C：Ginkgoの無細胞合成・閉ループ実験

2026年の研究例は、GPT-5と自動化基盤を接続し、無細胞タンパク質合成の条件を反復して評価する限定した用途である。[S08][S10] 汎用の実験を何でも無人で実行できるという実証ではない。

公開コードは、AIの実験設計をPydanticで検証し、Catalystが複数装置のワークフローへ変換してRACで実行する接続を説明する。[S09] これはコードで設計・実行・データをつなぐ実在の参考例になるが、公開リポジトリだけで商用ラボ全体をローカル再現できるとは限らない。

人が残る作業は、企業発表では試薬準備、装填・回収、システム監督とされる。[S10] 試薬の調達や検体配送、出荷までの完全無人化は、この研究の確認範囲ではない。論文は参照した公開記録ではプレプリントとして提示されている。[S08][S10]

写真：Ginkgo Bioworks提供、2026年2月の企業発表。[S10] 施設の実写真。写真だけから特定の研究に使った装置や全工程の無人化を推定しない。

画像：Ginkgo公式ハードウェアページ。[S11] ロボットアーム、プレート搬送トラック、接続点を示す説明画像。RACは装置を組み合わせる基盤で、カート単体がすべての実験機能を持つわけではない。

「公開確認」は文献が明示した範囲。「比較用想定」は部分自動化の例。「未確認」は資料から確定できないもの。一般的な写真や装置一覧から無人運用を補完しない。

6. 今回のデモに対応する仮想構成

基本構成：現場スタッフ付きの遠隔・統合ラボ

以下は今回の設計仮定。実在施設の能力・運用についての主張ではない。

担当・要素 役割
実験者 対象試料と実験計画を作成・承認。結果を受け取る
遺伝子合成会社 別施設として依頼配列を受け付け、製造・確認・発送。社内工程の自動化率は未設定
クラウドラボのスタッフ 検体受領・登録・装填・補充・例外対応。出荷を行う場合は梱包も担当
受付・計画・実行ソフト 注文ID、検体ID、計画版、実行IDを管理し、機器へ実行指示
分注装置 Biomek/Echo/Hamilton等に相当する機能を持つ分注器を1台以上。特定ブランドの実装とは結び付けない
搬送・温調・測定 必要な接続が用意された範囲で、プレートを運び、反応と測定を行う
結果保管・返却ソフト 測定結果と検体・実行を対応付け、利用者に返却

温調装置と蛍光プレートリーダーがあれば無細胞GFPを題材にできる、という機能上の設計例を置く。実機適合や方法の妥当性は未検証。無細胞系を例にする限り、生きた菌の培養を必須装置・工程にしない。

拡張構成：結果を次の計画へ戻す

解析ソフトやAIが次の条件を提案する接続を追加する。Ginkgoの限定用途を参考にできるが、受領・補充・保守・出荷まで無人になるとは仮定しない。初期版では、人が次の計画を承認する段階を残す。

関係図の矢印が具体的に意味するもの

デモの矢印 デジタル情報 物理的な移動／人の関与の仮定
実験者 ↔ 合成会社 依頼配列、注文、確認報告 DNA検体の発送は別の経路
合成会社 → ラボ 注文・検体・報告の対応情報 検体を輸送し、スタッフが受領・登録
実験者 → ラボ 対象検体、計画版、承認、実験依頼 ソフトが命令へ変換。必要な装填はスタッフ
ラボ → 実験者 実行IDと検体に対応する結果 物質の返送がある場合、別の発送工程
実験者 ↔ 自分の研究室 計画とデータの受け渡し 現場の手動操作と部分自動化。実際の経路は要確認

攻撃者はこの構成に必ず侵入できるとは置かない。接点・権限・防御の証拠が必要。外部通信を使うためのネットワークと、各装置を直接インターネットへ公開することも別である。

7. ボスと決める事項

  1. 基本想定は「スタッフ付き遠隔ラボ」でよいか。完全無人を要求する理由はあるか。
  2. 無細胞合成と蛍光測定だけで題材として十分か。培養・別の分析装置は必要か。
  3. 検体の受領・登録、装填、搬送、結果確認のどこを人が担うか。
  4. 結果返却で止めるか、次の計画の提案・承認まで対象にするか。
  5. 発注・確認報告・計画・結果について、どの形式や実システムを検証対象にするか。
