# リスク評価の基準案 v1

この表はシナリオごとの対応優先度を議論するための提案です。施設の潜在能力を分類するAST、CVSS、標準準拠評価とは別です。提案した対応表の妥当性はまだ検証していません。

## 評価する対象

一つのシナリオ、一つの構成と現行対策、今後12か月を評価単位とします。構成・入力経路・権限・防御・被害範囲が変われば再評価します。対策前の評価と対策後の評価を比較する場合も、前提をそろえて別に記録する必要があります。

起こりやすさは定性推定です。アクセス可能性や攻撃の難易度だけでなく、攻撃者の能力・意図・標的性、攻撃機会、防御の有効性を考慮します。攻撃が成立することを再現しても、現実の年間発生確率が分かったことにはなりません。

実測頻度は未測定です。頻度を数値化するには、監視期間・範囲・検知能力、観測した攻撃試行や被害の件数、分母となる実行数などの記録が必要です。観測ゼロは真の発生確率ゼロを意味しません。

## 起こりやすさ

| 段階 | 基準案 |
|---|---|
| L1 | 接点が限定的で必要条件が多く、有効な防御を確認 |
| L2 | 接点はあるが特別な権限・追加条件が必要。標的性・防御も含め中程度 |
| L3 | 攻撃機会が多く、成立条件が少ない。防御不足と攻撃者の能力・標的性に根拠 |
| L4 | 継続した攻撃や強い標的性が観測され、成立条件と防御不足を確認 |
| 未評価 | 構成・権限・防御・脅威情報が足りない |

経路が存在しないと確認した場合は、その構成では当該シナリオが対象外になるのであって、「極めて低い」の測定ではありません。現版の入力欄では未評価のまま、その理由に経路不成立を記録してください。

## 影響度

情報の秘密性、結果の正確さ、試料や装置の損失、停止期間、人・環境への影響を別々に検討し、根拠のある最大段階を選びます。組織の許容度に合わせて、金額・停止期間・対象試料の重要性などのしきい値を今後具体化してください。

| 段階 | 基準案 |
|---|---|
| I1 | 単一作業のやり直し。容易に復旧し、重要情報・試料・安全に影響なし |
| I2 | 単一実験の失敗、限定した検体・結果の損失。局所的で復旧可能 |
| I3 | 複数実験・貴重な試料の損失、重要データの漏えい、長い停止 |
| I4 | 人・環境への深刻な影響、または主要資産・活動を失う重大で回復困難な損失 |
| 未評価 | 被害の範囲や、その影響に至る条件を確認できていない |

「配列が差し替わる」と「毒性が生じる」「菌が死滅する」は別の条件と証拠を要します。前者だけを確認してI4にしないでください。

## 総合Tier：対応優先度の提案

| L / I | I1 | I2 | I3 | I4 |
|---|---|---|---|---|
| L1 | R1 | R1 | R2 | R3 |
| L2 | R1 | R2 | R2 | R3 |
| L3 | R2 | R2 | R3 | R4 |
| L4 | R2 | R3 | R4 | R4 |

R1：経過確認。R2：対策を検討。R3：優先して検証・対策。R4：実行前に責任者レビュー。

段階は順序尺度であり、L×Iの掛け算で被害期待値を算出しません。低いLでも深刻なIを埋もれさせない方針で、対応表を明示しています。L/Iの未評価、対象構成または評価理由の欠落はU（未評価）です。Uは低リスクではありません。

根拠の種類（仮説・文献・設定確認・再現）は自己申告の説明ラベルです。選択自体で根拠が確認されたわけではありません。再現が配列入力までか命令生成までか、物理・生物学的影響までかも理由欄で分けてください。

## 保存と共有

入力はシナリオごとに、このブラウザのlocalStorageに保存します。サーバーへ送信しません。他の端末や他の利用者には共有されません。保存が使えない場合はその旨を表示します。
